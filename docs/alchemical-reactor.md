# 錬金反応炉：初期実装

登録IDは `alchemical_power:alchemical_reactor`。専用ブロックモデルは四隅の支柱・観察窓・上面投入口を持つ1ブロックサイズの反応炉。窓内の液面は貯蔵量と現在のタンク容量に連動し、空のときは非表示。外部からの補充・加工中の消費・容量アップグレードもGUIを開かずに同期する。
GUIは提供画像 `textures/gui/alchemical_reactor_gui.png` を変更せず使用する。
反応炉のクラフトレシピと新素材は未定のため未追加。クリエイティブタブまたは `/give @s alchemical_power:alchemical_reactor` で動作確認できる。

## スロットと搬入

- 素材12枠（1枠4,096個、配置自由、同一素材を複数枠に分けても可）、非消費サンプル1枠、完成品1枠。
- 専用アップグレード5枠：ツール、速度、エネルギー効率、エネルギー容量、タンク容量の順。
- サンプルは完成品そのものを1個設置する。Shiftクリックで自動設定しない。
- 外部アイテム搬入は素材枠のみ、搬出は完成品枠のみ。全方向で利用可能。
- 液体は液体パナケイアのみを外部搬入できる。外部搬出や容器クリック操作はなし。
- FEは全方向から受電できる。外部への送電はしない。
- 加工中はサンプルとアップグレードを固定する。加工中以外でも、容量アップグレードを外すことで残量が基本容量を超える場合は取り外せない（液体・FEの消失防止）。

## Tierと容量

要求ツールTierは0～4（初心者、中級者、熟練者、究極、賢者の石）。未装着は0。
機械Tierが要求Tier以上なら加工可能。サンプルありのレシピとサンプルなしのレシピは混在せず、条件が不一致なら加工しない。

タンク容量はTier4以下では `2,000,000 × (1 + 3 × タンクTier)` mB。Tier5のみ基本容量の32倍（64,000,000 mB）とする。

| タンク | 容量 mB |
|---|---:|
| なし | 2,000,000 |
| T1 | 8,000,000 |
| T2 | 14,000,000 |
| T3 | 20,000,000 |
| T4 | 26,000,000 |
| T5 | 64,000,000 |

## 暫定バランス（後で相談して調整）

- 初期FE容量：100,000 FE（`AlchemicalReactorBlockEntity.BASE_ENERGY_CAPACITY`）。
- FE容量倍率：`1 + 0.8 × エネルギー容量Tier`。
- 速度倍率：`1 + 0.36 × 速度Tier²`。基本時間を割り、0.1秒（2tick）単位に切り上げ、最低2tick。
- 総消費FE：レシピの合計FEに `max(0.2, 1 - 0.15 × 効率Tier)` を掛け、切り上げ。
- 速度は加工時間のみ、効率は合計FEのみを変更。液体量と材料数は固定。
- 合計FEと液体量を加工tickに分配する。各tickの消費量は「次の進捗までの累積必要量－消費済み量」とし、整数丸めで合計が増減しないようにする。速度が上がると1tickあたりの液体・FE消費が増える。

ゲーム用加工レシピは最大 **119件**（うち4件はT7素材タグが空の場合に無効）。素材加工31件と燃焼のルーン18件に以下の統一基準を適用する。錬金基紙1件・キット4件・アップグレード32件・圧縮丸石製造機24件は既定の固定時間・固定FEを使用し、液体からのパナケイア復元9件は抽出機に対応する設定を使用する。
素材タグ `alchemical_power:t1_ingot_material` のアイテム1個＋液体216 mB＋合計5,000 FE、200tick（10秒）、要求Tier 0。
完成品1個をサンプルとして置き、完成品をさらに1個出力する。

素材加工・燃焼のルーンの易化レシピでは、液体消費量を `L` mB、境界値を `B = 1,000,000` mBとして、レシピの基本値を次の統一基準で設定する。

- 基本時間：`ceil(100 × (L / 216)^(1/4)) × 2` tick（0.1秒未満を切り上げ）。
- 基本合計FE（`L <= B`）：`ceil(5,000 × L / 216)`。
- 基本合計FE（`L > B`）：`ceil((5,000 × B / 216) × (L / B)^(1/4))`。
- 境界で丸める前の値を使い、最後に時間を2tick単位、FEを1 FE単位で切り上げる。時間は全域で1/4乗、総FEは100万mBを超えると比例から1/4乗へ切り替わる。
- 合計液体量から1回だけ計算する。高密度素材・結晶でも、中間素材の時間やFEを個数倍して積み上げない。液体量・固体材料・サンプル・要求Tierは変更しない。
- 計算結果を各レシピJSONの `time`・`energy` に記載する。速度・効率アップグレードはその基本値に適用する。

追加した確認用レシピ：

## JSON形式

`data/alchemical_power/recipes/alchemical_reactor/t1_panakeia_ingot.json` を参照。

- `ingredients`：最大12項目。各項目に `ingredient`（itemまたはtag）と `count`。
- `fluid`：`fluid`（液体ID）と `amount`（mB）。
- `sample`：非消費サンプル。省略するとサンプル枠が空のときのみ実行する新素材用レシピ。
- `result`：出力アイテムと個数。サンプル指定時は同じアイテムを指定する。
- `tool_tier`：0～4、`time`：基本tick、`energy`：基本合計FE。

新素材用レシピを追加する場合もこの形式を使える。模倣岩盤・特異点の易化レシピは追加しない。
同時に条件を満たすレシピがある場合はレシピID順で選択する。データパックでは重複を避ける。

## 加工・保存・表示

加工開始時に固体材料を1回分確保し、液体は各tickで必要な分だけ消費する。次のtickに必要な液体・FEが両方揃うまで、どちらも消費せず進捗を保持する。出力詰まりでも同様に停止する。
総液体量がタンク容量を超えていても、継続補給によって加工できる。ただし1tick分の液体・FEはそれぞれ機械に保持できる必要がある。
確保済み出力・進捗・液体の種類・総液体量・消費済み液体量・総FE・消費済みFE・演出対象を保存する。途中でブロックを壊しても、材料・サンプル・出力・アップグレード・液体・FE・加工途中の状態をブロックアイテムへ保存する。
旧バージョンの加工中データには総液体量の項目がなく、すでに全量消費済みなので、追加の液体消費なしで再開する。
別途アイテムをばら撒かないので、再設置による二重消費・二重取得は発生しない構成。

弧のゲージは白い下地の上に角度に応じた緑色／液体テクスチャを描画し、最後に元のGUI画像を重ねる。
ホバーで省略しない現在量／最大容量（FE・mB）を表示する。
素材の演出は確保した個数分だけを完成品枠へ移動する。余剰材料とサンプルは移動しない。進捗停止中は演出も停止する。
タンク容量・タンク残量・進捗は32bit整数、総液体量・消費済み液体量・総FE・消費済みFEは64bit整数として保存する。画面同期では16bitに分割し、通常のメニューデータの上限を超える値も保持する。レシピの総FE・総液体量も64bitで同期するため、クライアントとサーバーは同じ対応版を使用する。

JEIの表示領域は220×104ピクセル。時間とFEを1行にまとめ、素材12種類とアップグレード名を表示しつつ縦幅を抑える。
JEIカテゴリは材料、液体量、非消費サンプル、完成品、要求アップグレード、基本時間、基本合計FEを表示する。要求Tier 0は「なし」、1～4は対応するツールアップグレードのアイテム名を表示する。
GUI上部中央に機械名を表示し、その部分からJEIを開ける。下部の状態表示とそのクリック領域は設けない。サンプルを先に手動で設定する（サンプル不要レシピは空にする）。一致しなければ転送を拒否し、別レシピの誤加工を防ぐ。JEIの「＋」で1回分、Shift＋「＋」で機械に収まる最大の回数分の材料を配置する。既存の素材も利用し、余分な素材はプレイヤーのインベントリへ戻す。材料不足・戻す空き不足なら転送を行わない。サンプル、アップグレード、完成品、液体、FEは転送対象外。クライアントの確認後、サーバーがレシピIDと現在のインベントリから転送内容を再計算して確定する。

## 確認

Forge GameTestには消費量、電力不足時の停止、途中状態のアイテム保存・再設置、サンプル条件、出力詰まり、大容量タンク、外部搬入制限、重複条件を持つ素材の個数照合のテストを用意した。
テスト中に作るレシピオブジェクトは登録されず、ゲーム用レシピ一覧には含めない。

実機ではGUIのサイズ、アイテムと枠の位置、弧ゲージ、液体アニメーション、消費個数分の移動、JEIの表示を確認する。

2026-09-07の確認結果：`compileJava`、`processResources` 成功。GameTestは7件すべて成功。
GameTest起動には既存のCurios連携のため、通常のclient/server起動と同じMixinの名前変換設定が必要だった。
`JAVA_TOOL_OPTIONS` に以下を指定して当該プロセスだけに適用した（共有Gradle設定は変更していない）。

```text
-Dmixin.env.remapRefMap=true -Dmixin.env.refMapRemappingFile=F:/ideaProjects/alchemical-power/build/createSrgToMcp/output.srg
```

この環境のGradle wrapper JARは既存の0バイト状態のため変更せず、インストール済みGradle 8.8を使って `runGameTestServer --offline --no-daemon` を実行した。
結果ログ：`build/reactor-recipes-gametest.log`。クライアントのGUI描画は未確認。

素材転送の追加後：転送個数・最大回数・空き不足時の保全・12種類転送に関するGameTestを3件追加し、合計10件となった。今回のコンパイルおよびGameTestは実行要求が拒否されたため未実行。上記7件成功の記録は素材転送追加前のもの。

素材不足の転送エラーでは、1回分の必要個数を満たせない素材をJEI上でハイライトする。判定は機械内の素材12枠とプレイヤーの所持品36枠を合算し、重なる材料条件にも同じ素材を二重計上しない。サンプル不足の説明は括弧部分を別のツールチップ行として表示する。

アップグレードの取り外し制限は通常のアイテムツールチップに追記する。アイテム名と説明を維持した上で、取り外し不可・加工中・基本容量超過を赤字、減らす必要がある容量を灰色で表示する。複数の理由が同時に成立すれば両方を表示し、閾値はブロックエンティティの基本容量定数から取得する。

他機械にもアップグレードの取り外し制限と統合ツールチップを適用した。自動錬金組立機は加工途中、抽出機は処理対象を保持している間、発電機は燃焼中に取り外しを制限する。容量アップグレードは取り外し後の容量に収まる場合のみ取り外せる。発電機は残る3枠の倍率から容量を再計算し、抽出機は水・出力タンクを別々に判定する。通常クリック・Shiftクリック・外部抽出で制限し、理由と容量閾値はメニューで同期する（容量は16ビット分割）。起動確認はユーザーの指示がある場合のみ実施する。

総液体量はFluidStackのint量とは分離して保持する。JEIの数値・ツールチップは総液体量を表示する。旧int形式の総液体量はlongへ読み替え、旧来の全量前払い保存にも対応する。タンクとの授受は1tick分がタンク残量以下であることを確認してからintに変換する。
